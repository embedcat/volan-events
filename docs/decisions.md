# Журнал решений

Формат: решение — почему — что отвергли. Все записи ниже приняты 2026-10-20.

## Контекст

- **D01. Аудитория — один клуб**, в перспективе до трёх. Владелец события всё равно
  хранится, доступ проверяется по владельцу — переделывать при росте не придётся.
- **D02. Масштаб — средний**: 16–32 участника в категории, 3–6 категорий, 4–8 кортов.
- **D03. Сроков нет.**
- **D04. Интерфейс только на русском**, без инфраструктуры перевода.

## Предметная область

- **D05. Термины**: событие, категория, группа, партия (см. [domain.md](domain.md)).
- **D06. Код категории = разряд + уровень** (MSB, WDE, XDD). Разряды MS, WS, MD, WD, XD,
  а также открытые OS и OD.
- **D07. Уровень — необязательная свободная метка** (A, B+, B+C, 3). Отвергнуто:
  строгая упорядоченная шкала с проверкой допуска — границы между уровнями размыты.
- **D08. Общий справочник игроков** с рейтингом, клубом/городом, годом рождения, контактом
  и полем под ID всероссийской базы.
- **D09. Рейтинг ведёт внешняя система**; в заявке фиксируется снимок, рейтинг пары — сумма.
- **D10. Игрок может играть в нескольких категориях события** → очередь на корты общая
  на событие.
- **D11. Распределение по группам**: змейкой по рейтингу, без рейтинга — случайно,
  затем вручную.
- **D12. Снятие участника: сыгранное сохраняется, несыгранное — неявки.**
  Сознательное отступление от п. 2.12.1.6.4 правил (там аннулируются все результаты).
  Отвергнуто: аннулирование и настройка с выбором варианта.
- **D13. Счёт партии — только до 21 (предел 30) и до 15 (предел 21)**, разница 2 очка.
  Отвергнуто: произвольная настройка очков.
- **D14. Матч — 1 партия или до 2 побед**, решающая может быть до 15.
  Отвергнуто: ровно 2 партии с ничьей.
- **D15. Формат матча задаётся на этап категории.**
- **D16. Места в группе — по п. 2.12.1.6.3 правил** (победы → личная встреча →
  разница партий → разница очков → жребий). Отвергнуто: очки 2/1/0, мини-таблица.
- **D17. Неявка — сухая победа соперника** (2:0, 21:0). Совпадает с правилами
  для командных встреч (п. 2.12.1.7.8); для личных счёт правилами не задан.
- **D18. Отказ по ходу матча** — в протоколе фактический счёт, в таблице мест —
  сухая победа соперника.
- **D19. Матч на корт: система предлагает, организатор подтверждает.**
  Предлагается первый матч очереди со свободными игроками.
  Отвергнуто: автоматическая постановка, учёт отдыха в подсказке.
- **D20. Минимального отдыха нет**, время отдыха игрока показывается.
- **D21. Продолжительность = от вызова до ввода результата**, без кнопки «старт».
  Нужна для статистики, прогноза времени, планирования турниров.
- **D22. Табло для зала — после MVP**; до тех пор — публичная страница.
- **D23. Ввод — счёт каждой партии**, с проверкой и возможностью сохранить
  нестандартный счёт.
- **D24. История правок результатов в интерфейсе не нужна.**
- **D25. Роли**: суперюзер создаётся консольной командой; событием управляет только
  владелец; судей и соорганизаторов нет.
- **D26. Видимость**: черновик → опубликовано. Гостям видны фамилия, имя, клуб/город, рейтинг.
- **D27. Плей-офф (этап 2)**: из группы выходят двое; сетка крестом с разведением
  участников одной группы; розыгрыш мест настраивается; правка группы пересобирает сетку,
  пока в ней ничего не начато.

## Архитектура

- **D28. Без интернета событие ведётся с одного устройства**; при наличии интернета
  устройств сколько угодно. Отвергнуто: сервер в зале (ноутбук/RPi + локальный Wi-Fi)
  для одновременной работы нескольких устройств без интернета — лишнее железо
  и настройка ради случая, который не планируется.
- **D29. Любое устройство может работать без сети, конфликты показываются организатору.**
  Отвергнуто: явный захват события устройством, автоматически ведущее устройство.
- **D30. Работа без интернета входит в MVP** — в залах часто нет связи совсем.
- **D31. Событие и игроков можно создавать без интернета** → нужен инструмент
  объединения дублей игроков.
- **D32. Платформы**: Android, iPhone/iPad, ноутбуки.
- **D33. TypeScript везде** — правила турнира должны работать и в браузере, и на сервере.
  Отвергнуто: Rust → WebAssembly, сервер на другом языке с дублированием правил.
- **D34. Интерфейс — Svelte** (SvelteKit в режиме SPA, vite-plugin-pwa, Dexie).
- **D35. Сервер — Fastify + Drizzle + Zod, база SQLite.**
- **D36. Обновления — SSE + обычные HTTP-запросы.** Отвергнуто: WebSocket, опрос.
- **D37. pnpm workspaces, Vitest, Node 24 LTS.**
- **D38. Код на английском, комментарии и документация на русском.**
- **D39. Размещение**: VPS в РФ рядом с rockevents (Docker + nginx), volan.rockevents.ru.
  Репозиторий — GitHub.

## Объём

- **D40. MVP — одна категория, одна группа**, плюс работа без интернета.
  Итоги — печать и выгрузка JSON. Ввод счёта — поля по партиям.
  Тема — светлая и тёмная по системе.

## Модель данных (2026-10-20, второй заход)

- **D41. У события два независимых признака**: видимость (черновик / опубликовано)
  и ход (настройка / идёт / завершено). Отвергнуто: одна шкала — тогда идущее событие
  всегда видно гостям.
- **D42. Участники без рейтинга при змейке** — в конец, случайно.
  Отвергнуто: всё случайно, если рейтинг не у всех; требовать рейтинг.
- **D43. Событие хранится снимком `EventState` + журналом команд.**
  Отвергнуто: нормализованные таблицы (много кода на перевод состояния в таблицы),
  только журнал (риск при изменении правил в коде).
- **D44. ID новых сущностей и зерно жеребьёвки — в команде**, ID матчей выводятся
  из ID команды. Отвергнуто: временные ID на клиенте с переназначением сервером.
- **D45. Гости получают по SSE только сигнал «изменилось»** и заново запрашивают публичное
  представление. Отвергнуто: общий поток команд — пришлось бы вычищать закрытые поля.
- **D46. Отклонённые команды хранятся на сервере** и видны владельцу со всех устройств.
  Отвергнуто: только на устройстве-источнике.
- **D47. Опоздавший участник**: до первого вызова матча группы — пересборка расписания,
  после — дописывание матчей в конец очереди.
- **D48. Замена партнёра в паре — в любой момент**; у матча хранится фактический состав.
- **D49. Завершённое событие правится только после «вернуть в работу».**
- **D50. В заявке фиксируются рейтинг и клуб/город**; имя — из справочника.
- **D51. Справочник игроков правят автор записи и суперюзер**; объединяет суперюзер
  или автор обеих записей. Создаёт любой организатор. Отвергнуто: правят все;
  правит только суперюзер.
- **D52. Сессия — 30 дней с продлением, с отзывом.** Отвергнуто: 90 дней, бессрочно.
- **D53. Пароли — scrypt из `node:crypto`.** Отвергнуто: argon2id — лишняя нативная
  зависимость.
- **D54. Удалить событие владелец может, пока нет сыгранных матчей**; дальше — суперюзер.
  Отвергнуто: в любой момент; никогда.
- **D55. Явный старт**: матчи вызываются только после «Начать турнир».
- **D56. Завершение** — когда ни один матч не на корте; несыгранные остаются несыгранными.
- **D57. Выключить можно только свободный корт**; матч сначала переносится.
- **D58. Отмена вызова и стирание результата** возвращают матч в начало очереди.
- **D59. Результат можно ввести матчу из очереди** без вызова; продолжительность не считается.
- **D60. Фактический состав пары** фиксируется в матче при вводе результата.

## Экраны (2026-10-20)

- **D61. Пульт**: карточки кортов сеткой, под ними очередь; на телефоне — переключатель
  «Корты / Очередь». Отвергнуто: две колонки рядом, вкладки на всех устройствах.
- **D62. Ввод результата — окно поверх пульта**, на телефоне на весь экран.
  Отвергнуто: отдельная страница матча.
- **D63. Вызов на корт — с карточки корта (подсказка) и из строки очереди.**
  Отвергнуто: только перетаскивание, только с корта.
- **D64. Одни страницы для гостя и организатора**, владелец видит кнопки управления.
  Отвергнуто: отдельный раздел управления.
- **D65. Шахматка на всех устройствах**, на телефоне с прокруткой и закреплённой колонкой
  имён. Отвергнуто: список мест на телефоне, только список мест.
- **D66. Страница события — вкладки** (Корты/Пульт, Таблица, Матчи, Участники, Настройки).
- **D67. На телефоне навигация — панель внизу**, на широких экранах — вкладки сверху.
- **D68. Имена — «Фамилия Имя»** везде. Отвергнуто: «Фамилия И.», только фамилия.
- **D69. Печать в MVP — только итоговый протокол.** Отвергнуто на MVP: таблица для стенда,
  карточки матчей, список участников.
- **D70. Подстановка однозначного второго числа** при вводе счёта.
- **D71. Блока последних результатов на пульте нет**; правка — во вкладке «Матчи».
- **D72. Подтверждений нет, только «Отменить»**, для этого у каждой команды есть обратная.
  Исключение — удаление события: ввести название. Отвергнуто: корзина.
- **D73. Настройка до старта — одна страница со списком готовности.** Отвергнуто: мастер
  по шагам.
- **D74. Вставка списка участников текстом — после MVP.**

## Каркас репозитория (2026-10-20)

- **D75. pnpm ставится через corepack** в папку пользователя; версия — из `packageManager`.
  Отвергнуто: `npm install -g pnpm`.
- **D76. ESLint + Prettier.** Отвергнуто: Biome — слабая поддержка `.svelte`.
- **D77. TypeScript: strict + `noUncheckedIndexedAccess`.** Отвергнуто: только strict;
  максимальная строгость (`exactOptionalPropertyTypes` и т. п.).
- **D78. CI — GitHub Actions без хуков перед коммитом.** Отвергнуто: lint-staged; без CI.
- **D79. Пакеты отдают исходники TS; сервер — tsx в разработке, esbuild в продакшене.**
  Отвергнуто: сборка domain в JS через tsc. Встроенное снятие типов Node 24 не подходит:
  не работает для пакетов в `node_modules`.
- **D80. Имена пакетов — `@volan/domain`, `@volan/server`, `@volan/web`.**
- **D81. Интерфейс создан генератором `sv create`** (SvelteKit 3, adapter-static).
- **D82. Стиль — табы, одинарные кавычки, ширина 100.**
- **D83. TypeScript закреплён на 6.0.x**: инструменты не поддерживают 7.x.
- **D84. Защиту pnpm от слишком свежих версий не обходим** — ослабляем диапазон версии.
  Скрипты установки разрешены только esbuild (`allowBuilds`).

## Правила турнира в коде (2026-10-20)

- **D85. Ошибки domain — код + параметры**, тексты для людей — в интерфейсе.
  Отвергнуто: русские тексты в domain.
- **D86. Нестандартный счёт**: хотя бы одна партия, ничьих в партиях нет, победитель выиграл
  больше партий. Отвергнуто: без проверок с победителем вручную.
- **D87. Отказ**: завершённые партии — по правилам, последняя может быть не доиграна,
  матч к моменту отказа не решён. Отвергнуто: без проверок.
- **D88. Сильнейшие встречаются в последнем туре** (метод вращения, как у BWF).
  Отвергнуто: порядок добавления, случайный.
- **D89. Внутри тура матчи не переставляются.** Отвергнуто: перестановка, чтобы игрок
  не играл два матча подряд.
- **D90. ID матча — `<ID команды>:<n>`.** Отвергнуто: UUIDv5 (своя реализация SHA-1).
- **D91. Снявшийся ранжируется по результатам, как все.** Отвергнуто: всегда ниже активных.
- **D92. Несыгранная личная встреча пропускается** — дальше разница партий и очков.
  Отвергнуто: общее место до личной встречи.
- **D93. Нерешённое равенство — общее место «3–4» с пометкой.** Отвергнуто: временно
  по посеву.
- **D94. Жребий — когда все матчи группы сыграны**; действует только на тот же набор равных.
- **D95. Новое состояние — глубокая копия (structuredClone) и правка копии.**
  Отвергнуто: Immer, ручные развороты.
- **D96. Номер нового матча — наименьший свободный.** Отвергнуто: всегда продолжать.

Принято при написании кода, подтверждено kip:

- **D97.** При равном рейтинге порядок посева — жребий по зерну команды.
- **D98.** Рейтинг пары неизвестен, если рейтинга нет хотя бы у одного игрока.
- **D99.** Схемы Zod в domain — источник истины для формы состояния и команд, типы
  выводятся из них. Лишние поля в командах отбрасываются, у пустых команд — запрещены.
- **D100.** Отмена всех действий с матчем — служебная команда `match.restore`: матч
  возвращается целиком, только если его не меняли после отменяемой команды.
- **D101.** Снять участника можно только в идущем турнире; составить расписание группы
  со снятым участником нельзя (сначала вернуть или удалить его).
- **D102.** У неявки фактический состав пары (`lineup`) не записывается: на корт никто
  не выходил, и время отдыха такой матч не сбрасывает.
- **D103.** Опоздавший против уже снятого участника сразу получает победу по неявке.

## Сервер (2026-10-20)

- **D104. Пачка команд обрабатывается до конца**: отклонённая не останавливает следующие.
  Отвергнуто: остановка на первой отклонённой.
- **D105. Миграции — SQL-файлы drizzle-kit в репозитории, применяются при старте.**
  Отвергнуто: `drizzle-kit push`, SQL вручную.
- **D106. Ограничения попыток входа пока нет.** Отвергнуто на сейчас: 10 попыток
  за 15 минут на логин и IP.
- **D107. Закрытые поля игрока видят только автор записи и суперюзер** (уточнение D26).
  Отвергнуто: любой организатор.
- **D108. Остаёмся на better-sqlite3**: встроенный `node:sqlite` в Node 24 ещё
  экспериментальный, а стабильный Drizzle (0.45) его не поддерживает.

Принято при написании сервера, подтверждено kip:

- **D109.** Справочник синхронизируется по сквозной ревизии, удалённые игроки остаются
  метками; изменения справочника по SSE не рассылаются — клиент забирает их при запуске
  и синхронизации.
- **D110.** Защита от подделки запросов: изменяющие запросы только с JSON (text/plain
  отклоняется) + cookie SameSite=Lax.
- **D111.** scrypt с параметрами OWASP: N = 2^17, r = 8, p = 1 (≈128 МБ на вычисление хеша);
  параметры хранятся в самом хеше.
- **D112.** Суперюзер создаётся командой `cli user:create-superuser <логин>`, пароль —
  из `VOLAN_PASSWORD` или скрытым вводом в терминале; минимум 8 символов (как и для
  организаторов).
- **D113.** Сессия продлевается не чаще раза в час. При смене своего пароля остальные
  устройства выходят; при блокировке или сбросе пароля суперюзером — все.
- **D114.** Ответы о событии содержат имена игроков; публичное представление — состояние
  события без `ownerId`. Черновик для чужих — 404.
- **D115.** Удаление игрока, заявленного хоть в одном событии, отклоняется (`player.inUse`).

## Интерфейс (2026-10-20)

- **D116. Шаг 7 — четырьмя порциями** с показом и коммитом после каждой.
- **D117. Команды — сразу по итоговой схеме**: очередь отправки и применение на экране
  до ответа сервера; в шаге 7 очередь в памяти, в шаге 8 — в IndexedDB.
- **D118. Проверка интерфейса**: логика — Vitest, экраны — вручную во встроенном браузере;
  сценарии Playwright — в шаге 8.

Принято при написании порции 7a, подтверждено kip:

- **D119.** Порт и адрес сервера — `API_PORT` / `API_HOST`, а не `PORT` / `HOST`:
  общий `PORT` выставляют посторонние инструменты (так сервер занял порт интерфейса).
- **D120.** Ссылки и переходы — через `resolve()` (рекомендация SvelteKit 3, маршруты
  проверяются типами). Исключение — возврат после входа на сохранённый адрес.
- **D121.** Учётные записи для разработки — `cli dev:seed` (`admin`, `org`); в рабочем
  режиме команда отключена.
- **D122.** Переключатель темы — текстовая кнопка по кругу: как в системе → светлая → тёмная.
- **D123.** ID устройства пока в `localStorage` (в шаге 8 — в IndexedDB); ID новых записей —
  свой генератор UUIDv7 без зависимостей.

Принято при написании порции 7b, подтверждено kip:

- **D124.** Команда сначала проверяется правилами в браузере; если она недопустима, ошибка
  показывается сразу плашкой и команда не отправляется.
- **D125.** Своя команда держится поверх подтверждённого состояния, пока не вернётся по SSE.
  Если поток SSE не подключён, после ответа сервера состояние перечитывается целиком.
- **D126.** После создания события — сразу его настройки. Вкладки события делят одно
  хранилище, поток SSE открыт, пока открыта любая вкладка события.
- **D127.** Поиск игрока: слова в любом порядке по фамилии, имени и клубу, без учёта
  регистра и «е/ё»; в подсказках только подходящий по разряду пол, уже заявленные скрыты.
  «Новый игрок» подставляет строку поиска как «Фамилия Имя».
- **D128.** Настройки показывают одну категорию (MVP, D40), хотя правила допускают больше.

Принято при написании порции 7c — подтвердить:

- **D129.** Подсказки сразу для всех свободных кортов: по порядку номеров каждому — первый
  матч очереди, где никто не на корте и не в подсказке для корта раньше (`suggestForCourts`).
  Свободному корту без подсказки — пояснение: «очередь пуста», «все ожидающие игроки
  на кортах» или «свободные игроки — в подсказках для других кортов».
- **D130.** Ввод счёта: число считается дописанным, когда ещё одна цифра дала бы больше
  предела партии (до 21: «4»–«9», «0» и любое двузначное). Тогда — подстановка второго
  числа (D70) и переход к следующему пустому полю, после последнего — к «Сохранить».
  «2» или «3» дописываются переходом в другое поле. Подставленное число — с пунктирной рамкой.
- **D131.** В сыгранном матче сначала заполняются все показанные партии; только потом
  показываются нарушения правил и «Сохранить как есть». При отказе последняя партия может
  остаться пустой — отказ до её начала.
- **D132.** Окно результата запоминает результат, видимый при открытии: если его изменят
  с другого устройства во время ввода, сохранение станет конфликтом, а не перезаписью.
- **D133.** Меню «⋯» — встроенный в браузер popover (поверх всего, закрывается щелчком
  мимо и Esc), без библиотек. Окна — элемент `<dialog>`.
- **D134.** Перетаскивание строк очереди — встроенный Drag and Drop, только мышью;
  на телефоне — пункты меню: в начало, выше, ниже, в конец, на место N.
- **D135.** Шахматка: строки в порядке посева (не переставляются при вводе результатов),
  в заголовках колонок — фамилии. При отказе недоигранная партия в счёт по партиям
  не входит («1:0 отк.»). Равенство выделяется и «Жребий» предлагается, только когда
  сыграны все матчи. Жребий — окно с порядком ↑↓; действующий жребий отмечен «ж»,
  его можно изменить или снять.
- **D136.** Время на пульте пересчитывается раз в 20 секунд, пока его видно, — чтобы
  «14 мин» не отставали до минуты.
- **D137.** Адрес события без раздела у владельца: подготовка → настройки, идёт → пульт,
  завершено → таблица.
- **D138.** Список участников — один и тот же в настройках и во вкладке «Участники».
  «⋯» у участника: заменить игрока пары, снять (турнир идёт), вернуть, удалить (нет
  сыгранных матчей). В завершённом турнире — только просмотр.
